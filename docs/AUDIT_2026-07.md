# MeadEvil audit — July 2026

A full-pillar review (state/persistence, mead math, security/backend, UI/UX/a11y,
mentor/Brainstorm, workflow loop) plus a scripted real-user trial run.

This file records **what was fixed**, **what was deliberately not fixed and why**,
and **what is still open**, so the next session does not have to rediscover it.

---

## The two findings that mattered most

**1. Stored XSS, reachable without user action.** Record `id`s were interpolated
raw into `data-*` attributes at ~24 render sites (`data-recipe-edit="${recipe.id}"`
and friends) while every *other* value on those templates was correctly escaped.
`normalizeRecipe`/`normalizeLog`/`normalizeArchiveItem` trusted any inbound `id`,
and ids arrive from imported backups **and from cloud sync**. Proven with a repro:
the pre-fix code executed injected script on load with no interaction. Fixed at the
single choke point — `state-schema.js` now hard-restricts every id to
`[A-Za-z0-9_-]{1,64}` and regenerates anything else. All legitimate id shapes
(`recipe-abc12345-lx9k2`, `task-…`, `adj-test-1`, …) pass through untouched.

**2. The Finish tab handed out an ~8x sulfite/sorbate overdose during primary.**
The stabilizer dose rendered from the moment a recipe loaded, with no
`gateReady` check. Mid-ferment the measured ABV is tiny (day 2 of a 1.110 must
reads ~2%), and the sorbate model scales *inversely* with ABV — so the app printed
a bolded, authoritative gram figure several times too large, directly beside a
"Gate waiting" chip, contradicting the rule the docs state twice (§9, §13). The
dose is now withheld until two stable readings a week apart are recorded, and the
panel explains why.

## Test infrastructure was not actually testing anything

Three independent faults, all fixed:

- **No `package.json`.** `playwright` could not be installed, so neither suite could run at all.
- **Stale dialog driving.** The suites drove native `window.confirm` via
  `page.on("dialog")`, but commit `92ee5ee` replaced native dialogs with an in-app
  modal months earlier. Every destructive step silently did nothing.
- **`state()` read the wrong layer.** `app.js` persists `{_schema, data:{…}}`, but the
  helper returned the envelope — so `s.recipes`, `s.recipeDraft` and `s.archive` were
  all `undefined` and checks like "clone draft carries no stale id" passed
  **vacuously against an empty object**.

Two suites had also been failing since the commits that broke them, unnoticed:
`4f53c13` renamed the stabilizer output string, and `3b86e9d` made gravity-log
thinning variable-resolution (hourly for 72h, then 6-hourly) while its test still
assumed flat 6h buckets. Both tests now assert the intended behaviour.

`tests/user-journey.mjs` is new: it plays the documented loop end to end on the
repo's own reference recipe (Code Blue) and grades findings HIGH/MED/LOW by user
impact rather than by test convention.

## Fixed — mead math

| Was | Now | Why it mattered |
| --- | --- | --- |
| Free SO2 table shifted one row at pH 3.8/3.9 | Molecular-SO2 formula `0.8·(1+10^(pH−1.81))`, exact at every pH | 24% sulfite **overdose** at those pH values; also flat-lined above pH 4.0 |
| `Number("") === 0` treated a blank field as a real zero | `num()` returns `null` for blank/null/bool/array | Clearing a custom nutrient limit produced a **0 g schedule** while the panel still claimed it was hitting 235 ppm YAN |
| ABV via beer factor `(OG−FG)×131.25` | Cutaiar/Hall high-gravity formula | At OG 1.130/FG 1.000: 17.06% reported vs 19.31% real. Mead routinely starts 1.100–1.150 |
| `estimateRecipeTargets` inverted the *other* formula | Inverts the same formula (`ogForTargetAbv`) | Honey bill was planned on one model and yeast tolerance judged on another, so over-tolerance builds never warned |
| `Juice Concentrate` 48 PPG | 31 PPG | 48 is **physically impossible** — pure sucrose is 46 |
| `Fruit / Puree` 10 PPG, locked | 5 PPG, unlocked + per-fruit hints | Real fruit is 2–7 PPG; the Build target-vs-reality engine was being fed phantom gravity |
| oz/g source rows silently dropped | Converted | An all-ounce imported bill rendered as "no fermentables entered" |
| Nutrient panel headlined the **target** YAN | Reports delivered YAN and flags when caps bind | At high gravity the plan supplied ~227 ppm against a 426 ppm target while claiming success |
| Loss % > 100 → negative bottle counts | Clamped 0–100 | — |
| Step feeding never moved OG | Accumulates into an effective OG | ABV under-reported for the batch's life, which then **over-doses sorbate** |

## Fixed — data integrity and workflow

- **Starting a second batch destroyed the first.** The model is strictly
  single-active-batch and the replace prompt offered only discard-or-cancel, while
  tombstoning every gravity reading so cloud sync could not resurrect them. The
  prompt now offers **"Archive first, then start"**.
- **"Start batch" then "Save recipe" overwrote the wrong recipe.** `recipeLoad`
  moved `data.ui.selectedRecipeId` while the Build form still held a different
  draft; the next save wrote that draft over a recipe the user never opened.
- **Build draft edits rewrote a live batch's feed plan.** Sketching an unrelated
  experiment silently replaced the running batch's size, OG, dry yeast and nitrogen
  requirement. Now gated on recipe identity.
- **CSV re-import deleted everything CSV cannot express** — structure additions,
  acid/tannin plans, sources past the 6th. Now merges.
- **Import kept the previous device's mentor enhancement** when a backup carried
  none, fusing recipe A's ingredients with recipe B's botanicals.
- **Restoring a backup did not revive tombstoned ids**, so recovered records were
  stripped again by the next cloud merge.
- Malformed checklist items crashed `renderAll()` and blanked the whole app.
- Unreadable JSON silently presented an empty ledger — now backed up *and* announced.
- Blank log dates poisoned sort order and the 1/3-break decision.
- Toasts leaked: one shared timer meant the first toast never removed itself.
- Custom nutrient limits were destroyed by clicking a preset and back.
- Target YAN typed by hand was reverted on the next render.
- RAPT telemetry and the batch clock carried over into a new batch.
- The **Finish checklist** was created, cloned, archived and restored end to end —
  and never rendered. It now has a card.

## Fixed — security

- Mentor `ALLOWED_MODELS` included the expensive models, defeating its own purpose.
- No `max_tokens` (unbounded completion cost) and no upstream timeout.
- `Access-Control-Allow-Origin: *` on a function that spends the owner's API credit.
- `MENTOR_ALLOWED_ORIGINS` was undocumented; unset means **open to any origin**. Now
  documented in `docs/SETUP.md` and logged loudly on every request while unset.
- CSP + `nosniff` + `frame-ancestors 'none'` in `netlify.toml`; SRI on all three
  gstatic bundles. Verified: no inline handlers and no `<style>` blocks, so
  `script-src` needs no `'unsafe-inline'` (`style-src` does — inline style
  *attributes* are used for meter fills).
- `rapt-bridge` 5xx errors leaked env-var names and upstream Firestore messages.
- CSV export had no formula-injection guard.
- Browser-side mentor `fetch` had no timeout — a hung endpoint froze Brainstorm forever.

## Fixed — UI/UX and accessibility

- Checked checkboxes used `--purple` at **2.48:1** — the only hard WCAG 1.4.11
  failure, and the sole indicator of checked state. New `--purple-ui` at 4.80:1.
- `.btn:disabled` had **no styling at all**, so the mentor's Send button stayed
  fully lit and still ran its hover lift while disabled mid-request.
- Toasts sat on top of the two-row mobile tab bar and, being `pointer-events:auto`,
  swallowed navigation taps for 2.6–5.2s after every save.
- Inactive tab borders were 1.1:1 (invisible), violating the repo's own navigation
  guardrail; active was 1.7:1.
- `.tab-btn-meta` failed AA body contrast purely from an `opacity:.76`.
- ~256px of stacked dead scroll on every mobile screen; tab bar left-aligned
  between 530–720px.
- 23 accordions, **zero open** — a new user's first frame was grey placeholder bars.
  The primary task of Build/Ferment now opens by default.
- Source-bill inputs had no accessible names; "Remove source" was the only
  destructive action with no confirmation and no destructive styling.
- No `<h1>`; mentor status/reply announced nothing; coach-mode buttons had no
  `aria-pressed`.
- Long unbreakable strings were clipped unrecoverably by `overflow-x:clip`.
- The refractometer converter applies **no alcohol correction** and was labelled for
  exactly the case where it is most wrong. It now carries a pre-fermentation-only
  caveat (see open items for the real fix).

## Deliberately NOT changed

**Firebase sync uses one world-shared document.** `firebase-sync.js` syncs every
install to `meadevilApp/meadevil-shared` under `signInAnonymously()`. That is a real
exposure: anyone who loads the site can read and write it, and cloud data flows into
`localStorage` without normalization.

It was left alone because **the obvious fix breaks the feature**. Moving to a
per-uid document would scope the data correctly, but anonymous uids are per-browser
and do not survive a cache clear — so cross-device sync, the entire point, would
stop working. Doing this properly needs real linked auth (Google sign-in), which is
a product decision, not a bug fix.

Interim mitigation that *is* in place: the id sanitizer means a hostile shared
document can no longer inject script through the sync path.

**The Fermaid O constant (188.93 ppm/g/L).** Its measured YAN is ~40; the value here
is a TOSNA-equivalence figure back-solved to reconcile two functions. It is arguably
defensible inside TOSNA mode and clearly not defensible as a shared constant ranked
against DAP in the waterfall — but changing it moves every nutrient number in the
app. Now that the panel reports *delivered* YAN honestly, this is visible rather
than hidden. Worth a deliberate decision, not a drive-by edit.

## Still open, ranked

1. **Mentor provenance is misleading.** `buildPacketDrivenReply` answers greetings
   and acknowledgements from server-side templates *before* any model call, while
   the UI reports "GPT response received (gpt-4o-mini)". The first turn of every
   session is one of these. Local fallback output is likewise written into the
   transcript as a `role:"mentor"` turn, visually identical to real output, and fed
   back to the model as history. Tag every turn with its source and render it.
2. **There is no structured output.** The system prompt says "Do not output JSON";
   every field reaching Build is regex-scraped from prose. `callOpenAI` already
   accepts `responseFormat` and no caller uses it. A second cheap JSON pass would
   retire ~200 lines of scraping and fix the whole class of extraction bugs.
   (The honey-doubling case — a stated 7.5 lb total binding to two varietals and
   arriving as 15 lb — is now capped against the computed target, but that is a
   guard, not a cure.)
3. **Coach modes are cosmetic on the live path.** `mode` appears once in the prompt,
   as the bare label `Mode: scout`. Scout/Pushback/Forge are three buttons that do
   the same thing.
4. **The mentor's storage layer is envelope-blind.** It harvests from
   `main.recipeDraft` etc., which live at `main.data.*`, so the harvest is dead code
   and the merge bolts a phantom copy of the whole brainstorm thread onto every
   save — write amplification pushed to Firestore. Its writes also bypass the
   Firebase push scheduler, so mentor work never syncs.
5. **Cloud merge is whole-object last-write-wins** for `currentBatch`, `cellar`,
   `nutrients`, `recipeDraft` and the checklists. A pH recorded on the phone is lost
   when the laptop saves later. Tombstone *revival* is also not replicated.
6. **Refractometer alcohol correction.** The caveat added here is a stopgap; the real
   fix is the Terrill cubic, which needs an original-Brix input alongside the current
   reading.
7. **No racking/transfer log, so volume never changes after Build.** Backsweetening,
   bench-trial scaling, bottle count and stabilizer dosing are all linear in volume
   and all use the *original* batch size. A 3 gal fruit mead that packages 2.6 gal is
   told to add ~15% too much honey.
8. **The Source Bill does not drive gravity math**, despite being documented as the
   source of truth for it. `targetOg` is always recomputed from the design target;
   the bill's OG is display-only. Needs a UI decision: does the bill *replace* or
   *inform* the target?
9. **Design-system consolidation.** 56 hardcoded hex colours, 192 rgba values (24
   alphas of the same cream), 39 font sizes for what is a 6-step scale. Nothing is
   broken; the result is *soft* where the stated identity wants three decisive
   levels. Do the type scale only — leave the colours.
